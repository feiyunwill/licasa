# Licasa 0.6.0 release notes

Licasa 0.6.0 makes large photos quicker to preview, edit, and show at full detail. It also adds Fedora and Arch installation packages and strengthens Linux startup checks.

### Faster viewing and editing

- Large HEIF, JPEG XL, and PNG images can reuse pixels already decoded for their previews when full detail is requested. A 48 MP HEIF test reached full detail in 659–683 ms, down from 1051–1065 ms; a 48 MP JPEG XL test took 335–354 ms, down from 396–410 ms.
- Large TIFFs use a bounded preview reader for supported RGB and RGBA layouts. On the tested 64 MP TIFF, the first preview appeared in 127–150 ms instead of 332–342 ms. A shorter full-detail delay brought full detail to 561–600 ms, down from 990–1000 ms before the TIFF work.
- CPU color adjustments now process independent rows in parallel for large images. On the tested 48 MP RAW, the first exposure edit fell from 625–661 ms to 167–176 ms.
- A one-pass reader accelerates eligible large PNG previews when libpng is available. The full-resolution cache also avoids an unnecessary copy: on an isolated 64 MP PNG, peak memory fell from about 824 MiB to 576 MiB. Images with unsupported layouts or color metadata continue through the regular reader.
- Nearby-photo indexing starts in the background when a folder opens, reducing work on the viewer's UI thread. Decode-phase diagnostics are available for troubleshooting without logging photo paths.

These timings are local offscreen measurements on specific files, not promises for every photo or physical display. PNG wall-clock results varied under competing system load.

### Linux installation and startup

- Add an RPM for Fedora 44 and an Arch package. Both install the same AppImage payload without requiring FUSE at runtime and register Licasa as an image viewer. Neither package has a distribution repository yet.
- Retry once with software rendering if the initial Qt graphics context cannot be created. The Debian package and Snap include the Wayland runtime needed for native Wayland startup.
- Extend clean-install checks to look for a presented photo frame on virtual X11 and Wayland displays with default graphics settings and forced software rendering. Pull requests run the release build and tests; the full package and sanitizer workflow remains a separate release step.

Virtual-display checks do not establish performance or compatibility with every physical GPU and desktop session.

### Release files

- `Licasa-0.6.0-x86_64.AppImage` and `install-licasa-appimage.sh`: per-user installation on recent x86-64 Linux desktops. The AppImage uses Ubuntu 24.04 as its library baseline.
- `licasa_0.6.0-1_amd64.deb`: Ubuntu 24.04 amd64 package, installed with `sudo apt install ./licasa_0.6.0-1_amd64.deb`.
- `licasa-appimage-0.6.0-1.fc44.x86_64.rpm`: Fedora 44 package.
- `licasa-appimage-0.6.0-1-x86_64.pkg.tar.zst`: Arch Linux package. A matching `PKGBUILD` is included; publication to AUR is separate.
- `licasa_0.6.0_amd64.snap`: GitHub download with a SHA-256 checksum. The Snap Store build is first checked on `edge` and moves to `beta` only after the separate promotion approval.

Each downloadable package has a SHA-256 checksum. Background process remains optional in Settings.
